# SDA555XFL — reverse engineering v2

## Контроль образа

- Размер: 131072 байт (`0x20000`)
- CRC32: `B3680360`
- SHA-256: `6aa37c6d74d115eefdb52db8792b929b4104c59733485fc2c27a3402c2fce816`

Это тот же заводской образ, который был трижды прочитан одинаково.

## 1. Найдена заводская инициализация OSD

В reset-path, около `0x254D`, прошивка программирует указатели OSD:

```text
254D: MOV POINTARRAY0_L,#00h
2550: MOV POINTARRAY0_H,#04h
2553: MOV POINTARRAY1_L,#70h
2556: MOV POINTARRAY1_H,#04h
```

У SDA55xx указатели 14-битные и указывают внутрь XRAM `0xC000..0xFFFF`.
Поэтому заводская схема фактически использует:

- Pointer Array 0 -> `0xC400`
- Pointer Array 1 -> `0xC470`

Затем функция около `0x25FD` копирует шаблон из Program Flash `0x8F5F...`
в XRAM, начиная с `0xC400`. По работе с DPSEL видно использование двух DPTR:
один для Program ROM, второй для XRAM.

Общий размер копирования: **1126 байт**, то есть:
- ROM: `0x8F5F..0x93C4`
- XRAM: `0xC400..0xC865`

## 2. Полностью восстановлена карта OSD-памяти

### Pointer Array 0 @ C400

```text
C400-C401 = F448  -> Character Display RAM
C402-C403 = C410  -> CLUT
C404-C405 = C406  -> GDW / Cursor
```

### Pointer Array 1 @ C470

```text
C470-C471 = C476  -> 1-bit DRCS
C472-C473 = CC50  -> 2-bit DRCS
C474-C475 = CA16  -> 4-bit DRCS
```

Это не предположение по «похожим данным»: значения буквально лежат в заводском
шаблоне, который штатная прошивка копирует в XRAM.

## 3. Найдена точная геометрия экрана: 40 x 25 символов

GDW находится по `0xC406` и занимает 10 байт.

Начальные заводские байты:

```text
C406: 07 00 00 00 00 58 09 66 41 08
```

Byte 0 = `0x07`.

В нём `DISALH4..0 = 7`, а число колонок определяется как `33 + DISALH`.

Следовательно:

```text
33 + 7 = 40 колонок
```

Character Display RAM начинается по `0xF448` и доходит ровно до `0xFFFF`:

```text
0x10000 - 0xF448 = 3000 байт
3000 / 3 = 1000 экранных позиций
1000 / 40 = 25 строк
```

Итого заводской OSD:

**40 колонок x 25 строк = 1000 символов.**

Каждая позиция занимает 3 байта.

## 4. Найдена готовая функция вычисления адреса символа

Функция около `0x078E` делает:

```text
DPTR = F448h
DPTR += R5 * 78h
DPTR += R6 * 03h
```

`0x78 = 120 = 40 * 3`.

То есть практически наверняка:

```text
R5 = row
R6 = column
DPTR = F448 + row*120 + column*3
```

Это именно адрес одной ячейки 40x25.

Это очень ценный кандидат для повторного использования в нашем коде.

## 5. Найдена функция очистки/инициализации всего экрана

Функция `0x471B` начинает с:

```text
MOV DPTR,#F448h
```

и затем пишет по три байта на позицию, пока DPTR не пройдёт до конца XRAM.
Так как `F448..FFFF = 3000 байт`, функция обрабатывает ровно:

```text
3000 / 3 = 1000 = 40 * 25
```

То есть `0x471B` — фактически **полноэкранная функция заполнения/очистки OSD**.

## 6. Найдена инициализация аппаратного OSD

В startup:

```text
2592: MOV SCR1,#C0h
2595: MOV OSD_CTRL,#0Dh
2598: MOV SDH0,#BFh
259B: MOV SDV0,#28h
259E: MOV HCR1,#14h
25A1: MOV PSAVE,#07h
```

### OSD_CTRL = 0x0D

По документации F8h:

- bit 3: EN_LD_GDW = 1
- bit 2: EN_DG_OUT = 1
- bit 1: DIS_COR = 0
- bit 0: DIS_BLANK = 1

Главное: **Display Generator штатно включается** (`EN_DG_OUT=1`).

### SCR1 = 0xC0

Это устанавливает заводскую конфигурацию RGB DAC.
По полю `RGB_G1..0 = 10b` получается режим усиления RGB около **1.0 V** по таблице
Micronas.

### Позиция OSD

- `SDV0 = 0x28` -> вертикальная задержка 40 строк
- `SDH0 = 0xBF` -> горизонтальная задержка 191 пиксель (при старших битах = 0)

## 7. Почему standalone-видео потребует только отдельной работы с Sync Master

В достижимом startup-коде нет записи в `SCR0 (E2h)`.
После reset он остаётся `0x00`, то есть штатный телевизор работает в **slave sync mode**:
SDA555XFL получает синхронизацию от телевизионного тракта.

Это соответствует исходной схеме телевизора.

Для нашего самостоятельного компьютера ключевая задача не «изобрести OSD заново»:
OSD уже полностью найден и включается заводским кодом.

Нужно перевести Sync System в master mode и вывести собственные H/V или composite sync.

Это существенно упрощает проект.

## 8. Полезные заводские OSD-функции/узлы

Предварительные имена:

| Address | Предварительное назначение |
|---|---|
| `0x25FD` | загрузка базового OSD/XRAM template из ROM |
| `0x078E` | вычислить адрес ячейки `(row,column)` |
| `0x471B` | очистить/заполнить весь экран 40x25 |
| `0x4750` | загрузить часть программируемой CLUT из ROM |
| `0x4715` | изменить GDW byte 4 / border-related parameter |
| `0x46EC` | запись GDW byte 9 |
| `0x40AB / 0x40BB` | set/clear bit 0 в GDW byte 5 |

Названия последних функций пока рабочие: смысл параметров подтверждён адресами GDW,
но семантика конкретного UI-вызова требует ещё трассировки вызывающего кода.

## 9. GDW — дополнительные параметры заводской конфигурации

`GDW[6] = 0x09`:

- CHADRC = 1 -> **10 строк** в DRCS-матрице
- CHAROM = 1 -> **10 строк** у ROM-символов
- CHAAC = 0

`GDW[7] = 0x66`:

- DRCS boundary 1 index = 6 -> address 864
- DRCS boundary 2 index = 6 -> address 864

Так как обе границы равны, заводская конфигурация соответствует варианту,
где промежуточный диапазон 2-bit DRCS фактически может не использоваться как
обычный адресный диапазон символов. Сам XRAM-блок под него при этом существует.

## 10. Bank 1

В достижимом bank-0 коде обнаружены прямые записи в `MEX2`, в основном:

```text
MEX2 = 90h
MOVC A,@A+DPTR
MEX2 = 00h
```

Это штатное чтение данных из второго 64-KiB банка.

В рекурсивно достижимом коде не найдено прямой записи в `MEX1`, необходимой для
обычного переключения исполняемого code bank.

Рабочий вывод:

- bank 0 — основной исполняемый код;
- bank 1 — преимущественно ROM-ресурсы/таблицы.

Оговорка: остаются вычисляемые переходы, поэтому это не математическое доказательство
для каждого байта образа.

## 11. Самая перспективная стратегия

Теперь я бы **не переписывал видеосистему с нуля**.

Наиболее рациональный путь:

1. Сохранить заводской startup OSD.
2. Использовать его XRAM layout.
3. Использовать 40x25 Character Display RAM.
4. Переиспользовать адресатор `0x078E` или написать его эквивалент.
5. Первым собственным кодом менять только содержимое `F448..FFFF`.
6. Отдельно перевести Sync System в master mode для автономной работы без TDA8842.
7. Только после появления стабильной картинки — делать монитор/BASIC/клавиатуру.

Это уже очень похоже не на абстрактный эксперимент, а на реальный план создания
самостоятельного 8051-компьютера с аппаратным OSD.
